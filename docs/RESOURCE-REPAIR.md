# Восстановление ресурсов и исправления запуска

Применяйте патчи к исходникам mkxp-z в таком порядке:

1. `patches/mkxp-z-switch.diff`
2. `patches/switch-device-path.diff`
3. `patches/startup-diagnostics.diff`
4. `patches/switch-path-cache.diff`

Копируйте `patches/nxcompat.c` в `src/nxcompat.c` и собирайте движок. Порядок проверен на чистых исходниках: результат точно совпадает с исходниками собранного движка.

Исправления учитывают абсолютные пути `sdmc:/`, подключают папку игры по полному пути, пропускают пустые RTP и индексируют отдельные игровые файлы напрямую через `readdir`. Если индекс не находит ресурс, движок пробует точное имя UTF-8 и ASCII-псевдоним. Диагностика Ruby сохраняется на SD вместо невидимого диалога SDL.

FTP может читать существующее японское имя и одновременно отклонять создание другого японского имени. Поэтому недостающие ресурсы загружаются как `gamedata/nx-assets/<hash>`. Ключ — FNV-1a 64 от NFC UTF-8 относительного пути с расширением; только ASCII A–Z преобразуются в a–z. Исходные ресурсы не переименовываются.

Пример восстановления из своей копии игры:

```sh
python3 tools/repair-assets.py --source '/path/to/game' --host 192.168.31.40 --port 5000
```

Инструмент сверяет размеры оригинальных файлов и для отсутствующих или отличающихся файлов записывает ASCII-псевдонимы. Каждая восстановленная копия считывается обратно и проверяется по SHA-256. Результаты сохраняются в `asset-repair-report.json`. Во время работы держите FTP включённым. Повторный запуск поддерживается.

Игровые файлы, каталог `nx-assets` и отчёт с именами ресурсов не следует добавлять в Git. NSP-плитка запускает `/switch/BLACK_SOULS_DIAG.nro`; после обновления этого NRO переустановка плитки не требуется.

Подтверждено на консоли: подготовка графики и звука, запуск Ruby, выполнение 223 скриптов и появление титульного меню. После восстановления недостающих тайлсетов требуется проверка начала игры на консоли.

## Границы стека Ruby

Выделения 8 МБ через SDL недостаточно, если Ruby собран без HAVE_GETRLIMIT и HAVE_PTHREAD_GETATTR_NP: native_main_thread.stack_maxsize остаётся нулевым. Это подтверждено анализом первоначальной библиотеки и SystemStackError на консоли. Пересоберите thread.o Ruby 3.1.7, затем пересоберите движок с обновлённым patches/nxcompat.c:

```sh
python3 tools/rebuild-ruby-thread.py --source /path/to/ruby-3.1.7 --prefix /path/to/project/portlibs --build-dir /path/to/project/build/ruby-thread
```

Инструмент сохраняет резервную копию библиотеки, включает HAVE_PTHREAD_GETATTR_NP и PTHREAD_STACK_MIN, убирает настройку недоступного SIGVTALRM в Horizon и заменяет thread.o. Скрипт проверен полной компиляцией и повторной компоновкой движка. Реализация pthread_getattr_np читает stack_mem и stack_sz текущего Thread libnx, и журнал фиксирует реально переданные границы.

Полная сверка ресурсов на консоли завершена: проверены 3913 файлов по размеру, восстановлены 759 файлов (568885005 байт) под ASCII-псевдонимами; каждая восстановленная копия проверена SHA-256 после обратного скачивания. Появление титульного меню подтверждено пользователем. Проверка начала игры с пересобранным Ruby ещё выполняется.
